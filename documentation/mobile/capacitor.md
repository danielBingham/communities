# Capacitor

How the web client becomes the iOS and Android apps. The apps are the same
client bundle, running in a native WebView that
[Capacitor](https://capacitorjs.com/) provides, with plugins for the native
features it needs.

**Code:** `capacitor.config.js`, `android/`, `ios/`, `assets/`, `icons/`

## Configuration

`capacitor.config.js`, at the repository root:

| Setting | Value |
| ------- | ----- |
| `appId` | `social.communities` |
| `appName` | `Communities` |
| `webDir` | `web-application/public/dist/`: the client build. |
| `plugins.CapacitorUpdater` | `autoUpdate: false`: the client decides when to update. See [Live Updates](live-updates.md). |

It picks the native variant from `NODE_ENV` at build time:

| `NODE_ENV` | iOS scheme | Android flavor | App |
| ---------- | ---------- | -------------- | --- |
| `production` | `App` | `production` | `social.communities`, talking to `communities.social` |
| `staging` | `App Staging` | `staging` | `social.communities.staging`, "staging.Communities" |
| `development` | `App Local` | `local` | `social.communities.local`, "local.Communities", talking to `localhost:3000` |

The variants have different app ids, so all three can be installed side
by side.

## Building

`npm run build`, `npm run build-staging` or `npm run build-dev` (from the
repository root) build the client for that environment, then run
`npx cap sync`, which:

- copies `web-application/public/dist/` into the native projects
  (`ios/App/App/public`, `android/app/src/main/assets/public`);
- writes `capacitor.config.json` into each from `capacitor.config.js`;
- updates the native plugins to match `package.json`.

Those copies are generated and ignored by git.

## The Native Projects

`ios/` (an Xcode workspace, with CocoaPods) and `android/` (a Gradle
project) are generated by Capacitor and mostly managed by it.

| Change by hand | Leave to Capacitor |
| -------------- | ------------------ |
| Version and build numbers (released by maintainers) | Copied web assets and generated config |
| Per-variant settings: iOS schemes, `Info.plist` files and entitlements; Android flavors in `android/app/build.gradle` and `android/app/src/<flavor>/` | Plugin registration |
| App icons and splash screens | `capacitor.settings.gradle`, `capacitor.build.gradle` |
| Push notification and deep link setup (entitlements, intent filters) | |

Make native changes in Xcode or Android Studio, commit what they change,
and check all three variants still build.

## Plugins

Capacitor and its plugins are dependencies of the repository root
(`package.json`), which the native projects build against. The client
imports them too. Keep the versions in `package.json` and
`web-application/package.json` the same. Which plugins are used, and where,
is in [Native Features](native-features.md).

## Icons and Splash Screens

The source images are in `assets/` (`icon-only.png`,
`icon-foreground.png`, `icon-background.png`, `splash.png`,
`splash-dark.png`). `@capacitor/assets` generates the native icons and
splash screens, and the web icons in `icons/`, from them:

```
npx capacitor-assets generate
```
